# Agent Rules for `ausz`

## Implementation plans

Before implementing any ticket, create a doc under `docs/` with an implementation plan.

### Format

Put the plan at `docs/<ticket-number>-<short-title>.md` (e.g., `docs/12-config-implementation-plan.md`).

The plan must include:

1. **Crate dependencies** — all new crates with purpose
2. **Module structure** — files and their responsibilities
3. **Implementation order** — numbered steps in dependency order
4. **Validation rules** — what fails fast vs. what is deferred
5. **Acceptance criteria** — checkboxes mapping back to the ticket's acceptance criteria

### Why

- Prevents scope creep and forgotten edge cases
- Makes it easy to review the plan before writing code
- Creates a reusable reference during implementation
- Documents why certain design choices were made

### Process

1. Read the ticket thoroughly
2. Grill the ticket owner on any ambiguities
3. Draft the implementation plan in `docs/`
4. Review the plan (with the owner if needed)
5. Implement from the plan
6. Update the plan if scope changes during implementation
